# Opt-in M7 pool and timing diagnostics

Set `NS_M7_DIAGNOSTICS=1` on the serving process to enable source-owned aggregate
JSON snapshots prefixed `NS_M7_DIAGNOSTICS`. Default is OFF: pool/client methods
and asynchronous functions are not wrapped; no diagnostic worker, timer or clock
read is created. `NS_M7_DIAGNOSTICS_INTERVAL_MS` defaults to 5000 and accepts
1000 through 60000. An invalid interval leaves diagnostics disabled; absent
records are UNMEASURED. No HTTP endpoint, database query, authority cache or new
credential policy is added.

Labels are process PID and selected source role names only. Snapshots contain
fixed counters, gauges and 13-bucket duration histograms; they contain no tenant,
credential/token, request/socket ID, URL, SQL or error text. The registry tracks
at most 64 live pools. Overflow, unsupported query forms, missing roles and
zero-observation histograms are explicitly UNMEASURED, not zero-cost claims.

Observed pools are the normal PostgreSQL connection foundation, raw operation
lifetime pool, membership pool and registry provisioning pool. The two output
categories are `storage` and `operation`, aggregated across pools in that
process. Public pg.Pool total/idle/waiting counts are read directly; checkedout
is total minus idle (which can include a connecting client). `activeSQL` counts
outstanding observed client.query calls, including client-side query queuing;
it is not server pg_stat_activity state. Standard callback/Promise forms retain
result/error identity and callback `this`. Query instances/custom submitters and
config-owned callbacks are untouched and mark SQL coverage UNMEASURED. Query
calls are observed once, not separately at both pool.query and client.query.
Direct pg.Client activity, including the feed reader, is outside this pool
scope and explicitly UNMEASURED.

Lifetime gauges distinguish checked-out worker lease handles, queued critical
sections, active critical sections and active outer bodies. A shared lease
handle held through a response is not an active SQL query. Internal pending
queue cells include expired placeholders until the existing promise chain reaps
them; expiry ends the measured waiting span but does not rewrite queue behavior.
Admission, registration, API authorization, realtime authorization RPC/private
handler and completion are separate aggregate histograms. Registration includes
its admission subspan; `body_response_inclusive` includes authorization and the
actual response/provider lifetime. `complete_inclusive` includes its queue wait
and durable marker cleanup. These independent, overlapping histograms provide
no request-level causal pairing. Do not subtract percentiles or sum nested
spans to manufacture application-exclusive cost.

Output uses one unref'd sink worker with empty environment and no inherited
application preloads. It receives at most one transferred buffer of 8 KiB; there
is no snapshot queue. Busy/backpressured stdout, oversize output, partial write,
EPIPE or worker failure drops telemetry and marks missing coverage. The worker
writes only its diagnostic bytes; it never wraps or closes application stdout.
Shutdown neither waits for logging nor guarantees a final flush. The worker and
timer cannot keep application drain alive. This adds fixed per-process overhead
only while selected; same-source ON/OFF controls are required before using a
profile. An older profile without the hook has UNMEASURED diagnostics, not zero
wait or zero SQL. Capture the source and explicit diagnostic selection in the
profile manifest; legacy/Vault and local Ed25519 workloads remain distinct.

`tests/m7-diagnostics.integration.test.js` uses owned PostgreSQL/Vault and actual
API workers for held-pool/acquisition, pg_sleep, held-response/restore and ON/OFF
outcome controls. `scripts/test-m7-diagnostics-controls.js --native` compiles
exact source in owned child preloads, falsifies checkedout and omits outer-body
gauges, and requires the corresponding real-pool and actual-response oracles to
go red. It never edits a working source tree or remote harness.
