# Complete jsdom retirement

Decision: 2026-09-05, part of M08 and integration PR [#8605](https://github.com/nightscout/cgm-remote-monitor/pull/8605). Implementation PRs target `chore/nightscout-modernization`.

The goal is to remove the remaining test dependency while preserving observable regression coverage. The earlier production removal is already complete: `lib/server/purifier.js` uses `sanitize-html`, jsdom is a devDependency, and `npm ls jsdom --omit=dev` returns an empty tree at integration commit `8b57b7b8`. There is no further production heap or pruned-image saving to claim from deleting this test dependency. Measure developer/CI installation and test-process costs separately.

The jsdom 30 upgrade [#8613](https://github.com/nightscout/cgm-remote-monitor/pull/8613) was held as a draft fallback and is now closed without merging (verified 2026-09-05). Its native-global restoration fix and network-isolation tests are useful evidence; they do not establish a requirement to upgrade before removal. Evaluate any interim fix independently against the currently installed jsdom 26.1.0. Do not merge the major upgrade simply because its checks pass.

## Execution and acceptance

First slice: [#8615](https://github.com/nightscout/cgm-remote-monitor/pull/8615) replaces bundle smoke and the four served Socket.IO jsdom cases after Chromium/Firefox/WebKit comparison jobs passed on both exact Node floors. It adds required browser CI and measured test-tool costs; the remaining inventory still needs migration. See the [browser test specification](../test-specs/browser-tests.md). The [DOMPurify reference slice #8617](https://github.com/nightscout/cgm-remote-monitor/pull/8617) also merged after all required checks passed, moving all 15 cases without changing versions or production behavior. The next corpus slice maps all 300 differential/rendering cases and the production repeated-parsing case to the browser runner; other output-sink and UI consumers remain.

1. **Establish browser-test feasibility and baseline.** Evaluate a small Playwright-based suite against the actual built assets using the existing local browser probes as starting evidence. Keep browser automation development-only and pin its package/browser versions. Prove HTTP and WebSocket isolation, service-worker policy, fresh contexts, cleanup on success/failure and deterministic fixture setup. Compare install/download bytes, wall time and peak test-process memory with the existing harness; a downloaded browser may outweigh npm-package savings. Use one shared runner instead of introducing a second general unit-test framework.
2. **Prove one migration end to end.** Start with bundle smoke and the served Socket.IO browser-client checks, preserving their assertions alongside the existing tests during comparison. Add a required browser CI job on supported Node runtimes; keep backend MongoDB 5/6 matrix coverage. Use current supported-browser targets to decide browser-engine coverage before declaring UI parity. Demonstrate that a deliberately broken fixture/bundle fails the replacement check.
3. **Move pure logic and browser contracts in bounded PRs.** Begin with auth/storage and the existing client-core boundaries, then security/output sinks and remaining UI/report cases. Maintain a per-case mapping from each old assertion to a Node/browser replacement or an explicitly documented pre-existing quarantine. Preserve both glucose units, timezone/DST cases where applicable, repeated initialization/teardown and network failures. Do not delete coverage to make the package removable.
4. **Remove the package and retired harness.** Delete the direct declaration, now-unused helpers and jsdom-specific dependency-check entries; regenerate the lockfile without unrelated version changes. Confirm `npm ls jsdom --all` has no installed copies and scan source, fixtures, scripts, workflows and documentation for live consumers. Run clean installs, all Node/core/dependency and browser tests, production/development builds and both native Docker startup checks against the latest integration parent.
5. **Publish measured results and rollback.** Record net npm paths/bytes, browser-tool download/cache cost, CI duration and peak memory. Verify unchanged production dependency graph and user-facing behavior rather than promising additional server savings. Preserve a known-good test artifact; rollback a migration together with its harness/manifest changes, without altering application data. Close this item only after replacement coverage and removal are both complete.

Node 22/24 provide useful web APIs, but neither supplies the browser document, HTML parser, layout/event integration and window lifecycle used by these tests. Upgrading Node alone therefore cannot complete this removal. Avoid substituting another general DOM emulator merely to remove the jsdom name from the manifest.
